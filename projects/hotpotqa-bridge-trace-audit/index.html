搜得更多，为什么 Bridge EM 仍停在 47%？

我们没有马上再加一个 reward，而是重放 E1 已保存的逐步轨迹：先判断两篇必要证据有没有进入上下文，再检查后续搜索是否带来新的金标证据，最后把“没找全”和“找全仍答错”分开。

01

当前 Hybrid + Format checkpoint 共错 53 题：28 题结束时仍缺至少一篇金标证据；另有 25 题已经覆盖全部金标段落，却仍未通过 strict EM。

不能直接得出的结论

环境会先强制执行一次 bootstrap search，因此它不是模型主动生成的 query。审计将这次返回作为初始证据状态；每个后续 agent step 暴露的 passages 作为搜索后的新快照。

为什么两种 reward 的最终 coverage 一样

Hybrid + Format 确实触发了更多搜索，但逐题配对后只有 2 题相对 Hybrid 提升 recall，同时另有 2 题下降，96 题不变。它改变了行为频率，没有改变总体证据漏斗。

05

Format checkpoint 搜得更多，但单次搜索更低效

Hybrid + Format 的主动搜索题数从 22 增到 32，平均 query 从 0.29 增到 0.47；可观察搜索转移从 28 增到 45，但真正增加金标覆盖的次数仍然都是 18。

不要误读 search-conditioned EM

搜索组 EM 低于不搜索组，不代表搜索造成答案变差。更难、初始证据更差的问题本来就更可能触发搜索，这是明显的选择偏差。这里可靠的信号是：新增搜索没有带来对应的 evidence gain。

07

下一步先做 Gold-Evidence Oracle，不急着改 reward

当前 trace audit 已经把问题分成 retrieval 与 answer 两部分，但还不能判断哪一部分是主要上限。最便宜、信息量最大的实验，是把两篇金标 supporting paragraphs 直接提供给同一个 checkpoint。

同一批 100 BridgeCurrent Hybrid + Format checkpoint
Oracle EM 大幅上升

主要上限在 retrieval / query / termination。再设计 evidence-progress reward 或检索策略。

Oracle EM 仍然有限

主要上限在 answer synthesis / reasoning / exactness。优先修答案抽取与训练数据。

主实验

Gold Evidence Oracle：100 Bridge，固定 prompt、decoding、parser 和 checkpoint，只替换 evidence context。

回归控制

Comparison 子集继续保留，确保针对 Bridge 的改动没有破坏相对简单的问题。

后续 reward 候选

只有 oracle 证明 retrieval 是主因后，再测试基于 gold-title coverage 增量的 process reward。

为什么现在不直接奖励“多搜索”

现有结果已经说明调用次数不是目标：45 次可观察搜索只有 18 次增加金标覆盖。奖励 action count 会进一步放大重复 query 和过度搜索，应该奖励证据进展，而不是工具动作本身。

边界

Coverage 是段落标题级召回，不是 supporting sentence attribution；最后一个 tool call 若没有后续 agent step，其新结果不可观察；搜索条件下的 EM 有选择偏差；实验仍是单 seed、单 checkpoint 的诊断，不是因果证明。

Bridge failure decomposition

incomplete evidence + EM=0  28
full evidence       + EM=0  25

Conclusion:
Do not collapse both failures into one reward.
Run the gold-evidence oracle first.

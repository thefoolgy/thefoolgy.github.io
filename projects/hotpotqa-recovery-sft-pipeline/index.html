01

我真正想问的五个问题

先把问题凝练下来，再看实现，避免数字一多就失去主线。

  1. 状态计数为什么大于题目计数？100 道题形成 100 个 n=4 题组，为什么最终是 62 道题贡献 91 个 failure state，而不是“一题一个失败”？
  2. 147 个 query 如何验证？21 个 search state 各生成 6 个 self-teacher query 和 1 个 gold-derived curriculum query；“检索成功、正 evidence gain、不重复历史、不复用失败 query”四项条件具体怎样写进代码？
  3. 108 个成功记录为什么只留下 87 条？70 个 answer state 与 38 个成功 search attempt 为什么不能直接形成 108 条 SFT 数据？多路径去重和每状态上限怎样把搜索路径压到 17 条？
  4. 87 条怎样变成 800 个训练位置？replace=True 到底做了什么，它是在创造新数据，还是重复抽取同一批 row？
  5. 100 题 pilot 是否太小？独立 recovery 样本太少、failure 类型过度集中时，下一版应该扩大 rollout，还是仅靠提高过采样比例？

为什么 62 道题会产生 91 个状态：同一道题的四条 trajectory 可以在不同 step、不同 passages、不同 history 下失败。状态 ID 是 question_id + scenario + visible_state 的哈希；只有完全相同的可见状态才去重。38 道题没有产生满足 miner 条件的失败，另外 62 道题中的部分题产生了不止一个不同状态。

3 · real-tool verification217 records → 108 success70 answer + 38 search
4 · diverse selection108 → 87 rows70 answer + 17 search
5 · replay mixture87 → 800 slots加 7,200 core replay

失败状态怎样从 rollout 中挖出来

每条 trajectory 按 step 顺序扫描，只保存第一个可恢复 failure，然后立即 break。

远程源码/root/autodl-tmp/workspace/Agent-R1/recipes/hotpotqa/sft/build_recovery_sft.py:364-448
def _classify_failure(path, index, coverage):
    step = path[index]
    output = str(step.get("output", ""))
    queries = _parse_queries(output)
    state = _parse_state(output)
    history = parse_visible_state(str(step.get("input", "")))["history_actions"]
    feedback = parse_visible_state(str(step.get("input", "")))["tool_feedback"].casefold()

    if any(marker in feedback for marker in ("tool error", "jsondecodeerror", "timed out", "timeout")):
        return "tool_error_feedback"
    if float(step.get("evidence_state_valid", 0.0)) != 1.0 or state is None:
        return "protocol_error_feedback" if index + 1 < len(path) else None
    if queries and any(_normalize_text(query) in normalized_history for query in queries):
        return "repeated_query"
    if queries and float(step.get("search_coverage_gain", 0.0)) <= 0.0:
        return "zero_gain_search"
    if answers and coverage < 1.0:
        return "premature_answer"
    return None

`mine()` 在识别 failure 后，将 question、passages、history、tool feedback 和失败 action 固化成一个可见状态。对于 search/protocol/repeat failure，它读取下一轮 input，因为下一轮才包含工具执行后的 passages 或 feedback。Gold title 和 supporting sentence 只作为 verifier metadata，不进入 teacher/user prompt。

最终：44 个 positive-gain query − 6 个 failed-query reuse = 38 个 verified search attempts

70 + 38 = 108 是什么：它们是 verifier 判定成功的 recovery target records，其中 70 个是无需 search、自动标为成功的 answer states，38 个是 query attempts。它们不是 108 条新的 trajectory，也不会全部原样进入 SFT。

108 个成功记录怎样压缩成 87 条 SFT row

你的理解基本正确：真正训练“证据不足后继续搜索”的只有 17 条；其余 70 条训练“证据已足够，应停止搜索并回答”。

远程源码/root/autodl-tmp/workspace/Agent-R1/recipes/hotpotqa/sft/build_recovery_sft.py:724-749
def _select_diverse(attempts, limit):
    answer_attempts = [
        x for x in attempts
        if x.get("target_mode") == "answer" and x.get("verified_success")
    ]
    if answer_attempts:
        return answer_attempts[:1]

    ranked = sorted(
        (x for x in attempts if x.get("verified_success")),
        key=lambda x: (
            0 if x.get("candidate_source") == "gold_derived_curriculum" else 1,
            -float(x.get("evidence_gain", 0.0)),
            -float(x.get("supporting_sentence_gain", 0.0)),
            len(str(x.get("verified_query", ""))),
        ),
    )
    selected = []
    for attempt in ranked:
        if any(_query_similarity(attempt["verified_query"], x["verified_query"]) >= 0.8 for x in selected):
            continue
        selected.append(attempt)
        if len(selected) >= limit:
            break
    return selected

87 条为什么能写成 800 个训练位置

不是生成新语义，而是 Pandas 有放回抽样：每次抽完后仍把该 row 放回池子，因此同一 row 可以多次出现。

远程源码/root/autodl-tmp/workspace/Agent-R1/recipes/hotpotqa/sft/build_recovery_sft.py:874-893
core = pd.read_parquet(args.base_sft_train)
target_rows = 8000
wanted_recovery = round(target_rows * 0.10)  # 800
recovery = pd.DataFrame(recovery_rows)       # 87 unique rows

sampled_recovery = recovery.sample(
    n=wanted_recovery,
    replace=wanted_recovery > len(recovery), # 800 > 87, therefore True
    random_state=42,
)

sampled_core = core.sample(n=7200, replace=False, random_state=42)
mixed = pd.concat([sampled_core, sampled_recovery], ignore_index=True)
mixed = mixed.sample(frac=1.0, random_state=42).reset_index(drop=True)
mixed.to_parquet("train.parquet", index=False)

实际统计中，每个独立 recovery path 在混合训练文件里出现 3 到 19 次，平均 9.2 次。所以 recovery.parquet 保存 87 条独立 row，而 train.parquet 中有 800 个标记为 training_source=recovery 的位置。它提高出现频率，但不会提高场景覆盖度。

09

100 题 pilot 太少吗？是，而且问题不只是数量

更好的方向是增加独立 failure state 和类型覆盖，而不是继续提高 87 条数据的重复次数。

当前瓶颈 1

Search recovery 只有 17 rows

70/87 是“已有充分证据后停止搜索并回答”；真正训练下一跳 query 修复的独立状态只有 9 个。

当前瓶颈 2

Failure 分布高度偏斜

最终 76/87 来自 zero-gain search，没有真实 tool-error、repeated-query 或 empty-result 训练数据。

当前瓶颈 3

过采样不能创造覆盖

同一 target 重复十次可以提高权重，但模型仍没有看过新的错误上下文和恢复策略。

  1. 扩大真实 rollout mining。从 100 题 pilot 扩到至少 500–1,000 个 train questions，并使用多个 seed/temperature；继续保持 Eval-200 question-level 隔离。
  2. 按 failure type 和 question_id 限额。不是无脑收集更多 zero-gain search；对同一题、同一 state、同一 scenario 设置 cap，优先补 tool error、empty result、repeat、partial-evidence 和 distractor correction。
  3. 所有 teacher query 仍需真实执行验证。即使使用 DeepSeek API 或 gold-derived curriculum 生成候选，也必须经过真实 retriever，并检查正 evidence gain 与 query novelty。
  4. 目标是减少或取消 recovery oversampling。更理想的是获得接近 800 条独立且分布可控的 recovery rows，而不是让 87 条重复填满 800 个位置。
  5. 运行 matched control 和两套 eval。同一 step-250 起点比较 core-only 50 steps 与 90/10 recovery mix 50 steps；同时跑 Recovery Stress Eval-200 和标准端到端 Eval-200。
8 月 4 日结论：本轮证明了 rollout → failure state → teacher candidate → real-tool verifier → SFT row → replay mixture 工程链路能够闭环，但没有证明 recovery capability 已提升。下一门禁不是继续长训，而是扩大独立恢复数据、平衡 failure taxonomy，并完成 matched behavioral evaluation。

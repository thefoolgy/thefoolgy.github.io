这一行为什么重要

Dynamic Sampling 的准确位置

先生成并算 reward，再筛 group；凑满后才进入 PPO/GRPO 更新

它解决的是 optimizer batch 里大量 group reward 完全相同、导致组内 advantage 全为 0 的问题。它不把 0 改成非 0，而是拒绝这些组并补采有差异的组。

1. Step row → trajectory

AgentFlow 会把一条多步 trajectory 展成多行。helper 先按 trajectory_uids 对 row reward 求和，否则会把同一轨迹的工具步骤误当成多个 rollout。

2. Trajectory → prompt group

再按 prompt uid 收集 n=4 个完整轨迹回报，计算标准差。全 1 或全 0 的 group 被丢弃，有高有低的 group 被保留。

3. Filter → refill

第一轮只保留 B、D 两组，不够 train_batch_size=4，L1133 的 continue 回到 dataloader；注意 global step 此时没有增加。

4. Refill → optimizer batch

第二轮 E、F 也通过 gate，和 B、D 用 DataProto.concat 合并。选满 4 组后，才计算 old log-prob、advantage 和 Actor loss。

uid

prompt group 的主键。同一问题的 n 条 rollout 共享它，GRPO 用它做组内比较。

trajectory_uids

一条完整 Agent rollout 的主键。同一轨迹展开出的多个 step row 共享它。

step row

AgentFlow 的训练物理行。一次 search、一次 observation 后的 response 都可能形成一行，因此 row 数通常大于 trajectory 数。

算法边界

Dynamic Sampling 提高“有信号 group”的占比，但改变了采样分布，也会增加 rollout 成本；必须同时记录 acceptance rate 和生成批次数。

源码快照：AgentR1/Agent-R1 官方 commit b124aa4 加本地 Dynamic Sampling overlay。页面示例只用于解释 shape 与控制流，真实实验结论以 checkpoint、日志和 matched ablation 为准。

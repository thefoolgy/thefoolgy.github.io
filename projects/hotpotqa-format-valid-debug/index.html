D0 · Validation Pipeline Debug

从一个 None 追到轨迹级指标契约

新增 strict-format reward 后，训练在初始 validation 崩溃。这份记录保留完整证据链：异常发生在哪一层、如何排除 reward 公式、为什么只修复 format_valid，以及如何证明训练闭环真的恢复。

日期 2026-08-01 框架 Agent-R1 + veRL 任务 HotpotQA 状态 根因确认 · E2E smoke 通过

01 · 一句话结论

新 reward 函数本身可以返回合法数值；真正的问题是，一条在 max_steps 处以工具调用结束的轨迹没有 final-answer reward payload，导致其最后一步的 format_valid=None。validation 将它与其他浮点数一起交给 numpy.mean，因此在 optimizer step 开始前崩溃。

这次 Debug 的核心价值 没有把表面上的 NoneType 错误误判成 reward 权重问题，而是把它定位为 interaction-level 数据进入 trajectory-level metric 时缺少终止语义。

02 · 改动目标与故障现象

此前 P2 实验出现了“答案 token 更接近，但输出格式反而变差”的 reward-eval 错配。为此，我新增 compute_score_hybrid_format，要求最终答案严格使用唯一的 <answer>...</answer>，并把训练分数写成：

answer_score = 0.2 * EM + 0.8 * token_F1
train_score  = 0.9 * answer_score + 0.1 * format_valid

函数同时返回 em、token_f1 和 format_valid，方便在 validation/W&B 中观察各 component。第一次 smoke 在初始 validation 阶段报错，尚未执行 actor update：

TypeError: unsupported operand type(s) for /: 'NoneType' and 'int'

process_validation_metrics(...)
  metric[f"mean@{n_resps}"] = np.mean(var_vals)

堆栈停在 metric aggregation，而不是 compute_score_hybrid_format。这个阶段判断直接排除了学习率、GRPO advantage、backward 和显存等方向。

03 · 定位过程：沿 traceback 反推数据

排查顺序不是盲目加日志，而是从消费端 np.mean(var_vals) 反向追踪 var_vals 的来源。

步骤观察推断或排除
1. 阅读最后一帧堆栈np.mean 在除法时报 NoneType / int待聚合列表不是纯数值，至少混入一个 None
2. 单独检查 reward 返回正常答案、缺失标签、重复标签、尾随文本等反例均返回 0.0 或 1.0strict parser 的常规分支没有直接返回 None
3. 检查 20 条 validation 轨迹19 条最后一步为 format_valid=1.0；1 条为 None问题来自单条轨迹的特殊终止形态，不是整个 batch
4. 回看异常轨迹轨迹耗尽 max_steps，最后动作仍是 tool call，没有 final answer工具步骤没有 final-answer reward payload，空 component 不能直接作为轨迹指标
5. 追踪聚合代码ray_trainer.py 无条件取每条轨迹最后一步的 extra info“逐 step 可为空”与“轨迹 metric 必须是数值”之间缺少接口契约

完整数据流被压缩为：

trajectory 最后一步是 tool call
  -> 没有 final-answer reward payload
  -> reward_extra_info["format_valid"] = None
  -> 取最后一步作为 trajectory metric
  -> process_validation_metrics
  -> np.mean([1.0, 1.0, ..., None])
  -> TypeError

04 · 根因：interaction 与 trajectory 的指标契约

Agent-R1 的 reward extra info 是 interaction-level 数据；validation 要把它压成 trajectory-level metric。原实现对所有 component 使用同一规则：“取最后一步”。这隐含了一个未写明的假设：

每条轨迹的最后一步都提交了 final answer，而且所有 extra metric 都是有限数值。

正常完成的轨迹满足这个假设；达到最大步数后仍在调用工具的轨迹不满足。因此根因不是 reward 公式算错，而是截断轨迹的语义没有映射到 format_valid 的数值域。

从任务定义看，没有提交最终答案就不可能满足最终答案格式，所以这里应当定义为 0.0，而不是继续保留为“未知”。

05 · 修复前后代码差异

修复前：最后一步是什么值，就原样加入轨迹级数组。

for key, values in reward_extra_info.items():
    batch_traj_extra_info[key].append(
        make_json_safe(values[last_step_idx_in_traj])
    )

修复后：先读取最后一步，再只对 format_valid 补齐截断语义。

for key, values in reward_extra_info.items():
    value = make_json_safe(values[last_step_idx_in_traj])
    # A trajectory that exhausts max_steps with a tool call has
    # no final-answer reward payload, so its format is invalid.
    if key == "format_valid" and value is None:
        value = 0.0
    batch_traj_extra_info[key].append(value)

补丁位于 agent_r1/trainer/ppo/ray_trainer.py 的 trajectory metric 聚合边界，而不是 NumPy 或通用 reward 公式中。

  1. 语义明确：没有 final answer 就是格式不合法，故为 0.0。
  2. 改动最小：只处理已知 component，不把所有 None 粗暴转换成零。
  3. 不掩盖未来错误：没有在通用 process_validation_metrics 中静默过滤空值。

06 · 验证：不只是让异常消失

修复后的标准是完成整个训练闭环，而不是只看 TypeError 是否消失。

07 · 工程结论与测试债务

  1. 新增 reward component 就是在新增接口契约。除了正常答案，还要覆盖 timeout、max-steps、tool error 和无 final answer。
  2. 先判断失败阶段。初始 validation 崩溃时，optimizer 尚未运行，不应从 RL 超参数开始排查。
  3. 可聚合指标必须是 total function。进入 mean/std 的字段必须对每条样本都有数值语义。
  4. 修复靠近语义边界。在 trajectory aggregation 处解释“截断且无 final answer”，比在 NumPy 层过滤 None 更透明。
  5. 仍需补回归测试。加入“最后一步为 tool call 且达到 max-steps”的测试，并单独记录 truncated trajectory ratio，避免 format-valid 同时承担格式质量和完成率两种解释。

08 · 面试中如何讲这次 Debug

我给 HotpotQA 的 hybrid reward 增加格式 component 后，训练在初始 validation 的 NumPy 聚合阶段失败。我先根据 traceback 确认 optimizer 尚未执行，再对 reward parser 做反例测试，排除常规返回分支。随后检查 20 条轨迹，发现 19 条为数值，只有一条在 max-steps 处以 tool call 结束，最后一步没有 final-answer payload，导致 format_valid 为 None。根因是 interaction-level extra info 转成 trajectory metric 时缺少截断语义。我没有全局过滤 None，而是在聚合边界仅将该字段映射为 0.0，最后通过初始评测、16 条 rollout、真实 backward/optimizer step 和最终评测验证修复。

事实边界 这次实验验证的是 validation/训练闭环恢复和指标契约修复，不代表一次 optimizer step 已经证明模型获得稳定泛化收益。
